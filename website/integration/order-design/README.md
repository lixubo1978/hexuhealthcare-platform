# 荷序顾客点单界面新版

依据顾客点单录屏重新设计，保持项目、门店、技师、来源、预约四步选择逻辑。页面为独立可点击设计演示，没有订单或支付请求。此次并未修改工程师已有订单程序，因为只收到录屏，没有收到该程序源码或接口。

## 文件
public/order-design.html / .css / .js / -data.js；assets包含荷叶顶图、操作图版式样例、现有荷序logo。放到同一网站静态目录即可预览；本地双击HTML也可操作（浏览器本机图片预览能力可能不同）。网页中的返回首页由原项目提供。

## 视觉
中文字体优先PingFang SC、Microsoft YaHei；16px正文、清晰字重。顶图中文由HTML呈现，可修改且不会缩放模糊。手机横向分类、左图右文卡片；电脑两列卡片与左分类。照片固定区域裁切，可在CSS改object-position。保留固定底部选购条。

## 操作图片
每个项目包含 images:string[] 和 imageAlt 字段。images[0]为项目封面，点击打开多图详情。每项目最多6张展示图片。推荐封面4:3或3:2，至少800像素宽。照片应是获得展示授权的实际项目图，不含客户可识别敏感资料。当前肩部放松照片仅为版式样例，并非乳腺疏通实拍，正式上线必须替换。

顶部“更换项目图片”是设计人员用的本机预览：读取JPG/PNG/WEBP，每张8MB以内，验证可解码；不上传、不保存到后台，刷新恢复。在正式顾客页移除此工具和演示提示，把图片维护放到现有管理员项目编辑中。后台应完成权限、文件内容、大小校验，持久保存URL并返回到项目字段。不要让顾客在点单页面编辑图。

## 接回原程序
以原程序服务端的正式项目/分类数据替换演示数据；保留原项目ID，不使用演示编号。价格、库存、门店可用项目、技师项目认证与门店关联、预约时段由现有后端返回并校验。

客户手机号登录沿用原程序。正式下单需提交项目ID与数量、门店ID、技师ID、来源类型及已认证关联人ID、预约北京时间。多项目同单要由后端判断门店和技师能否履约全部项目，不能默认兼容。来源关系优先由可信链接/系统已有绑定识别，避免任意自由输入账号影响分成。

本演示“查看订单预览”仅显示提醒，没有真实创建订单、支付、库存占用或分账。工程师应将按钮绑定原createOrder流程，保留服务器价格计算、重复提交防护、支付确认、核销和退款逻辑。客户的应付金额以服务器计算为准。后台真实订单完成创建后跳转原订单详情页，订单号与倒计时必须由服务器返回，不在前端伪造。

录屏中的折扣、模拟支付等不作为正式价格或付款功能复制。演示300/100来自录屏，仅用于版式，与门店真实报价无关。当前城市/门店/技师为展示数据；上线接动态列表和合法的城市定位授权。

## 验收
检查手机宽度320/375/390/430和电脑宽度；200%文字缩放；分类切换、数量和合计、四步选择、返回保留选择、未选阻止继续、日期与来源关联人校验、图片插入、多图查看、图片失败占位。正式接入后再做真实订单与支付回归。
